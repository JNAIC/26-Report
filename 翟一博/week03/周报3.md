## 一、数据准备：三步把数据喂进网络

```python
x, y, xt, yt = load_mnist("data")
train_loader = DataLoader(TensorDataset(torch.from_numpy(x), torch.from_numpy(y)),
                          batch_size=128, shuffle=True)
test_loader = DataLoader(TensorDataset(torch.from_numpy(xt), torch.from_numpy(yt)),
                         batch_size=512)
```

| 部件 | 作用 |
| --- | --- |
| `torch.from_numpy()` | 把 numpy 数组转成 torch 张量（**零拷贝，共享内存**） |
| `TensorDataset` | **配对**：按下标把第 i 张图和第 i 个标签绑成一组 |
| `DataLoader` | **分批**：按 `batch_size` 切片，按需逐批吐出 `(xb, yb)` |
| `shuffle=True` | 每轮重新排序；不写则默认为 `False`（顺序不变） |
| `batch_size` | 一批的样本数：训练 128，测试 512 |

**关于 `shuffle=True` 的机制**：它不改变数据本身，而是每个 epoch 生成一个新的**索引顺序**（`RandomSampler`）。所以原始数据一直没动，随时能按原顺序取到第 0 张。

**训练批小、测试批大的原因**：训练批小（128）→ 一轮更新次数多（60000/128≈469 次），且随机噪声有助泛化；测试只做推理不更新参数，批大（512）更快。

## 二、模型结构

### 2.1 一次完整前向传播：从一张图到 10 个分数

```
第一层卷积 Conv2d -> ReLU(nn.ReLU()) -> 池化(nn.MaxPool2d(2))
 -> 第二层卷积 Conv2d -> ReLU -> 池化
 -> 展平 nn.Flatten()
 -> 全连接 nn.Linear() -> ReLU -> Dropout(0.25)
 -> 全连接 nn.Linear()  -> 输出 10 个分数，分别对应 0~9
```

```python
model = nn.Sequential(
    nn.Conv2d(1, 32, 3, padding=1), nn.ReLU(), nn.MaxPool2d(2),    # 28 -> 14
    nn.Conv2d(32, 64, 3, padding=1), nn.ReLU(), nn.MaxPool2d(2),   # 14 -> 7
    nn.Flatten(),
    nn.Linear(64 * 7 * 7, 128), nn.ReLU(), nn.Dropout(0.25),
    nn.Linear(128, 10),                                            # 10 个类别分数
)
```

形状流动：

```
(N,1,28,28) → (N,32,28,28) → (N,32,14,14) → (N,64,14,14)
            → (N,64,7,7) → (N,3136) → (N,128) → (N,10)
```

### 2.2 各层的作用

**`nn.Sequential(...)`**：一个顺序容器。数据从第 1 个层进去，一路流到最后。它自己是个 `nn.Module`，所以能 `.to(device)`、能 `.parameters()`、能 `model(x)`。额外好处是可以用下标取某一层 —— `model[0]` 就是第一个 `Conv2d`（打印卷积核就是这么取的）。

**`nn.Conv2d(in_channels, out_channels, kernel_size, padding)`**

| 参数 | 含义 |
| --- | --- |
| `in_channels` | 输入通道数。灰度图 = 1；上一层的输出通道是几，这里就填几 |
| `out_channels` | 32 个卷积核 = 输出 32 张特征图 = 32 个通道 |
| `kernel_size` | 核大小 3×3。**注意是边长，不是"3 个核"** |
| `padding=1` | 四周各补 1 圈 0，抵消"卷一次少 2 像素"，输出保持 28 |

**关键点**：第二层的核不是平面的 3×3，而是"32 层 × 3×3"的一个**小立方体**。因为第一层输出了 32 个通道，第二层的每个核必须在所有 32 个通道上同时取窗口。所以"64 个核" = 64 套这样的立方体，每套产出 1 张特征图，合起来 64 个通道。

**`nn.ReLU()`**：`max(0, x)`，逐元素、没有参数。作用是引入**非线性** —— 没有它，两层卷积在数学上等价于一层卷积。

**`nn.MaxPool2d(2)`**：2×2 窗口取最大值，步长默认 = 窗口大小 = 2（所以不重叠），没有参数。边长减半、计算量降到 1/4。

**`nn.Flatten()`**：把 `(N, 64, 7, 7)` 压成 `(N, 3136)`，默认从第 1 维开始合并（第 0 维是批量，不能动），没有参数。

压缩后的新下标：**`偏移量 = c*49 + i*7 + j`**（例如第 0 个通道第 0 行第 0 列的下标就是 `0*49+0*7+0 = 0`）。`Flatten()` 干的事就是"把这个公式算出来的偏移量直接当新下标"，所以展平后顺序完全不变，只是索引方式从"三坐标"变成"一个数"。

**`nn.Dropout(0.25)`**：随机失活，一种**正则化**手段。

- 训练时对输入的每个元素以概率 `p=0.25` 置 0，并把保留下来的元素除以 `(1-p)`
- **为什么要除以 (1-p)**：保证输出的期望值不变。不除的话，训练时这一层总输入偏小、预测时突然变大，行为不一致
- 不加 Dropout 时，强特征会让某几个神经元变得"很能干"，其他神经元逐渐废掉（**共适应 co-adaptation**），模型依赖特定组合 → 过拟合
- 加了之后，每个神经元都有 25% 概率"被临时下岗"，网络不能依赖任何单个神经元，必须把知识分散存储 —— 相当于每次训练一个略有不同的子网络，最后相当于集成了一大堆子网络

**`nn.Linear()`**：全连接层。

1. 第一个全连接是 `64*7*7 = 3136` 个数到 128 个数的映射。"映射成 128 个数" = 造了 128 个不同的加权求和公式，每个公式都看全部 3136 个输入；每个公式有 3137 个参数（3136 个 w + 1 个 b）；经 128 个公式得到 128 个输出
2. 第二个全连接是 128 个数到 10 个数的映射，原理同上

### 2.3 参数量怎么算

```
conv1:  32×1×3×3  + 32      =     320
conv2:  64×32×3×3 + 64      =  18,496
fc1:    3136×128  + 128     = 401,536
fc2:    128×10    + 10      =   1,290
─────────────────────────────────────
总计                          421,642
```

参数量的大头在第一层全连接（占 95%），卷积层反而很省 —— 这就是"权重共享"的价值。

## 三、训练过程

整个训练代码分 5 个部分：**准备、外层循环、内层五步、评估、收尾**。

### 3.1 准备阶段

**`nn.CrossEntropyLoss()` —— 损失函数（criterion）**：内部含 `log_softmax` + `NLLLoss`，所以喂进去的是**原始分数（logits）**，不是概率。输入要求 `input (N,10)` 浮点、`target (N,)` 的 `int64` 类别下标；输出是一个 0 维标量（这一批的平均损失）。它算的是 `-ln(模型给正确答案的概率)`，错得越离谱损失越大。

**`torch.optim.Adam(model.parameters(), lr=1e-3)` —— 优化器**：Adam（Adaptive Moment Estimation），一种自适应步长的一阶优化算法。

| 要素 | 含义 |
| --- | --- |
| `model.parameters()` | 一个生成器，递归遍历所有 `nn.Parameter`（需要梯度的张量） |
| `lr=1e-3` | 学习率，步长的基准值 |

### 3.2 外层循环：epoch

| 概念 | 定义 |
| --- | --- |
| **epoch（轮）** | 把训练集的全部样本完整过一遍 |
| **iteration / step（迭代步）** | 处理一个 batch、更新一次参数（不是单独的变量名，内层 `for` 每循环一圈就是 1 个 step） |
| **batch（批量）** | 一次前向传播同时处理的样本数，这里是 128 |

`60000 / 128 ≈ 469` 个 step = 1 个 epoch；训练 3 个 epoch ≈ 1407 次参数更新。

### 3.3 模式切换

**`model.train()` / `model.eval()` —— 切换训练 / 评估模式**，影响 `Dropout` 和 `BatchNorm` 的行为：

| 模式 | Dropout | BatchNorm |
| --- | --- | --- |
| `train()` | 随机丢弃一部分神经元 | 用当前 batch 的均值/方差 |
| `eval()` | 关闭（全部保留） | 用训练时累积的运行统计量 |

这两个切换必须放在 epoch 循环**里面**，因为每一轮都要"训练 → 评估 → 再训练"来回切。评估时忘了 `model.eval()`，Dropout 仍然生效，准确率会虚低且每次结果不同。

### 3.4 内层循环五步

**① `opt.zero_grad()` —— 梯度清零**

清除所有参数的 `.grad` 累积值。`backward()` 是**累加**而不是覆盖 —— 这是有意的设计（支持"梯度累积"之类的技巧）。不清的话，第 2 批的梯度里会混着第 1 批的，更新方向就全错了。

**② `loss = loss_fn(model(xb), yb)` —— 前向 + 损失**

`model(xb)` 得到 `(128,10)` 的 logits，再交给损失函数算出标量 loss。前向过程中，每个运算都会被记录成一个节点（见 ③）。

**③ `loss.backward()` —— 反向传播**

术语：自动微分（autograd）的**反向模式**，按**逆拓扑序**遍历计算图，用链式法则逐层求导。

一句话：**loss 是一个"带记忆的标量"，`backward()` 顺着这份记忆做链式法则。**

1. `loss` 这个数记得自己是怎么算出来的 —— 因为前向过程中每一个运算都被记录成了一个节点
2. 每个节点都存了两样东西：**输入是谁**（图的边）和**这个运算的导数公式**（`grad_fn`）。这些节点连起来就是**动态计算图（DAG）**，挂在 `loss.grad_fn` 上
3. 图就是"运算的依赖关系 + 每一步的导数公式"的登记簿。PyTorch 在前向时边算边记（所以叫"动态图 / define-by-run"），`backward()` 时逆着登记簿往回走，一路乘过去

`backward()` 结束后，每个参数都有了 `p.grad`，形状与 `p` 完全相同。

**④ `opt.step()` —— 更新参数**

参数更新（parameter update），执行优化算法的一步迭代：读 `p.grad`，按 Adam 的公式算出步长，**就地修改**参数。

顺序不能乱：`zero_grad → 前向 → loss → backward → step`。忘了 `zero_grad` 会导致梯度跨批累加，loss 震荡不降。

**⑤ `total += loss.item()`**

`.item()` 把 0 维张量转成 Python 的 `float`。这一步不能省 —— 如果直接 `total += loss`，`total` 会变成**带计算图的张量**，每轮把整张图挂在上面，内存持续增长（不报错，只是越跑越慢甚至 OOM）。

### 3.5 评估块

```python
model.eval()
correct = 0
with torch.no_grad():
    for xb, yb in test_loader:
        correct += (model(xb).argmax(1) == yb).sum().item()
```

**`with torch.no_grad()`**：禁用 autograd 的记录上下文。评估只做前向、不需要梯度，不开的话会白白建图、占内存、慢 20~30%。

**`model(xb).argmax(1)` —— 取预测类别**

| 步骤 | 输入形状 | 输出形状 | 含义 |
| --- | --- | --- | --- |
| `model(xb)` | `(512,1,28,28)` | `(512,10)` | 10 个类别的 logits |
| `.argmax(1)` | `(512,10)` | `(512,)` | 沿类别维取最大值的下标 → 预测类别 |

`argmax(1)` 的 1 是维度：第 0 维是批量（每个样本单独取），第 1 维是类别（10 个里取最大）。**写错成 `argmax(0)` 就是在"跨样本比较"，结果全错。**

**`== yb`** 判断对错 → **`.sum()`** 数对的个数 → **`.item()`** 转成普通整数。

**`total / len(train_loader)` —— 平均 loss**：严格说这是"批平均"，不是"样本平均" —— 最后一批不足 128 张，会让平均值略微偏差，精确写法是 `sum(loss_i * batch_size_i) / N`。

**`correct / len(yt) * 100` —— 准确率**：`len(yt)` 是测试集样本数（10000），不是批次数。

### 3.6 收尾

**`os.makedirs(path, exist_ok=True)`**：创建目录。`exist_ok=True` 表示"已存在就跳过，不报错"（幂等）；没有它，第二次运行会抛 `FileExistsError`。

**`torch.save(model.state_dict(), path)`**：保存参数。

`state_dict` 是一个有序字典 `OrderedDict[str, Tensor]`，只含参数和缓冲区，**不含网络结构、不含优化器状态、不含梯度**。加载时要先建同结构的模型：

```python
model = CNN()                                      # 结构必须一致
model.load_state_dict(torch.load("results/mnist_cnn.pt"))
model.eval()                                       # 预测前记得切评估模式
```

不要用 `torch.save(model)`（存整个对象）—— 那把类定义也腌进去了，换 Python 版本或改代码路径就加载失败。**存 `state_dict` 是标准做法。**

## 五、遇到的问题

- **`argmax` 的维度写错**：一开始写成 `argmax(0)`（跨样本比较），准确率接近 0，改成 `argmax(1)` 才对
- **忘记 `zero_grad()`**：梯度跨批累加，loss 震荡不降，排查后才明白 PyTorch 的梯度是累加的
- **`total += loss` 忘了 `.item()`**：内存持续增长，训练越跑越慢
- **加 Dropout 之后评估没写 `model.eval()`**：准确率虚低且每次结果不同
- **`torch.save(model)` 与 `torch.save(model.state_dict())` 的区别**：前者把类定义也存进去，换路径就加载失败，改用 `state_dict`
- **`total / len(train_loader)` 是批平均不是样本平均**：最后一批不足 128 张会有微小偏差
